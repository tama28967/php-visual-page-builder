# PHP Visual Page Builder

A local-first, offline-capable visual page builder built on PHP 8 native code,
MySQL/MariaDB, and [GrapesJS](https://grapesjs.com/) as the drag-and-drop
design engine. This is not WordPress and not Elementor — it is a small,
modular PHP application that uses GrapesJS purely as its visual editor
component; all drag/drop, styling, layers, devices, and undo/redo come from
GrapesJS itself.

The builder's job ends at HTML + CSS. Pages are stored in MySQL and can be
exported as static HTML/CSS or as PHP-wrapped files, ready for you to extend
with real PHP logic afterwards.

## 1. Installation

1. Install [XAMPP](https://www.apachefriends.org/) (Apache + MySQL/MariaDB + PHP 8.x).
2. Start **Apache** and **MySQL** from the XAMPP control panel.
3. Copy this project folder into your XAMPP `htdocs`, e.g.:
   ```
   C:\xampp\htdocs\php-page-builder
   ```
4. GrapesJS is already vendored locally at [`grapesjs/grapes.min.js`](grapesjs/grapes.min.js)
   and [`grapesjs/grapes.min.css`](grapesjs/grapes.min.css) — no CDN, no
   internet connection needed at runtime. (These were fetched once via `npm`
   during development purely as a packaging step; the app itself never talks
   to npm or any CDN.)
5. Open the app in your browser, e.g. `http://localhost/php-page-builder/`.
   Since no admin account exists yet, every page automatically redirects
   you into the **setup wizard** (`setup.php`) — a 3-step flow similar to
   Moodle's installer:

   - **Step 1 — Database.** Enter your MySQL/MariaDB host, database name,
     username, and password. The database is created automatically if it
     doesn't already exist, and the credentials are written to
     `config/installed.php` (generated, not committed — this file marks the
     app as "installed"). No existing data is ever dropped.
   - **Step 2 — Admin Account.** Tables are created automatically, then you
     set the first admin username/password (min. 8 characters).
   - **Step 3 — Done.** Setup is complete; click through to `login.php`.

   You can also open `setup.php` directly at any time — it always shows
   only the step that's still needed, and once installed it lets you add
   further admin accounts from the same page.

### Changing the default admin account

There is no hardcoded production password. The admin account is whatever
username/password you type into the wizard's Step 2 form. To add more
admins later, revisit `setup.php` — once installed it shows an "Add
Another Admin" form. To reset a password, use phpMyAdmin to update the
`password` column in `users` with a value from PHP's `password_hash()` —
never store a plain password there.

### Redoing the database step

`config/installed.php` is what marks the app as installed — if it's
missing, every page redirects back to the setup wizard. To reconfigure the
database connection (e.g. you moved to a different MySQL server), delete
`config/installed.php` and revisit `setup.php`; it will not touch your
existing database or tables, it only rewrites the connection credentials.

## 2. Offline Use

Everything the app needs at runtime is local:
- GrapesJS (`grapesjs/grapes.min.js`, `grapesjs/grapes.min.css`)
- All application CSS/JS (`assets/css`, `assets/js`)
- PHP backend + MySQL

There are no CDN links, no Google Fonts, no external API calls anywhere in
the served pages. Once installed, you can disable your network connection
entirely and the builder (login, dashboard, editor, save/load, preview,
export) keeps working.

## 3. Project Structure

```
php-page-builder/
├── index.php / login.php / logout.php / dashboard.php / editor.php / preview.php / setup.php
├── api/            AJAX endpoints (pages, media, templates, export) — JSON in/out
├── config/         config.php (paths/session), database.php (PDO connection),
│                   installed.php (generated by setup.php — DB credentials)
├── includes/       auth.php, functions.php, exporter.php, header.php, footer.php
├── assets/css|js/  app/dashboard/editor styles, editor.js + blocks/devices/storage/export modules
├── grapesjs/       vendored GrapesJS build (local, no CDN)
├── uploads/images/ user-uploaded media (validated images only)
├── exports/        transient ZIP staging area (cleaned up after each download)
├── templates/       reserved for future on-disk template assets
└── database/schema.sql
```

## 4. Creating a Page

1. From the dashboard, click **+ New Page**.
2. Set a **Page title** and a **slug** (e.g. `/` for the home page, `/about`
   for an About page, `/contact` for Contact). Slugs are sanitized
   automatically — only letters, numbers and hyphens survive.
3. Drag blocks from the right-hand Blocks panel onto the canvas: Layout
   (Section, Container, Row, Columns...), Basic (Heading, Text, Button...),
   Media (Image, Video, Gallery), Content (Hero, Card, Pricing, Contact...),
   Advanced (Custom HTML).
4. Select any element to edit its styles in the Style Manager (Layout,
   Typography, Background, Border, Effects), switch Desktop/Tablet/Mobile in
   the top bar to add responsive overrides, and use Undo/Redo as needed.
5. Click **Save**. The page's HTML/CSS is written to the `pages` table.
6. Click **Preview** to see the page rendered standalone in a new tab.

## 5. PHP Template Support

The visual editor **never executes PHP**. What you build is exported as
plain HTML/CSS. If you want to make a page dynamic afterwards, add
placeholders like `{{title}}` or `{{description}}` as plain text inside the
editor, save/export as usual, then hand-edit the exported `.php` file:

```php
<h1>{{title}}</h1>
```
becomes, after your own edit:
```php
<h1><?= htmlspecialchars($title) ?></h1>
```

The exported PHP files are static HTML wrapped in a `<?php ... ?>` comment
header — they contain no logic pulled from the editor. You add the dynamic
parts yourself, after export.

## 6. Export

### Single page
From the editor top bar, click **Export**:
- **Export HTML** — downloads `index.html` for the current page.
- **Export CSS** — downloads `style.css` for the current page.
- **Export HTML+CSS ZIP** — downloads a small ZIP with `index.html`,
  `style.css`, and any referenced `images/`.

### Whole website
From the dashboard, click **Export Website**:
1. Choose **All Pages** or tick specific pages.
2. Choose format: **HTML/CSS** or **PHP**.
3. Click **Export ZIP**.

You get `website-export.zip` (HTML/CSS) or `website-php.zip` (PHP), with:
```
index.html (or index.php)   ← page with slug "/"
about.html                  ← page with slug "/about"
css/style.css                ← combined CSS from every exported page
js/script.js
images/                      ← only images actually used, copied from uploads/
README.txt
```
Internal links (`href="/about"`) are rewritten to the exported filename
(`href="about.html"`), and uploaded image URLs are rewritten to the
relative `images/...` path — so the extracted folder is fully portable and
works with no builder, no PHP, and no internet connection (HTML/CSS export),
or on any PHP-capable server (PHP export).

## 7. Running Fully Offline

1. Complete installation once while online (so GrapesJS's vendored files and
   `npm`-fetched assets are already in place — no further npm/network access
   is needed afterwards).
2. Disconnect from the internet.
3. Visit `http://localhost/php-page-builder/`, log in, create/edit a page,
   drag & drop blocks, save, reload the editor, preview, and export a ZIP.
   Everything should work identically with no network access.

## 8. Known Limitations

- The `templates/` on-disk folder is reserved for future thumbnail/asset
  storage; template HTML/CSS today lives entirely in the `templates` table.
- There is a single role (any logged-in user can manage all content) — no
  per-user page ownership beyond the `user_id` foreign key already enforced
  on every query.
- PHP export produces a static wrapper only; turning `{{placeholders}}`
  into real dynamic PHP is a manual step by design (see section 5) so that
  the editor can never execute arbitrary PHP.
